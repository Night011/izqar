# IZQAR: сценарий демонстрации для жюри

## Перед показом

1. В корне проекта запустите `powershell -ExecutionPolicy Bypass -File .\scripts\start_local.ps1`; для React-панели в отдельном PowerShell выполните `cd frontend; npm run dev` и откройте `http://127.0.0.1:5173`.
2. Возьмите `IZQAR_API_KEY` из локального `.env` и введите его в форму входа. Не показывайте ключ на экране трансляции.
3. Проверьте `GET /health` и карточки моделей на странице **ML Analytics**. Отсутствующую модель называйте отсутствующей: её метрики и прогнозы интерфейс не имитирует.
4. Уточните в начале: операции симулятора синтетические, их оценка получена Rule Engine; ML-модели обучены и оцениваются отдельно на своих датасетах.

## Показ за 5 минут

| Время | Действие | Что показать и сказать |
|---|---|---|
| 0:00–0:45 | **Обзор системы → Обычная оплата** | Операция попадает в журнал, где видны сумма, правило оценки риска, решение и объяснения. Метрики панели отражают только локальную демо-базу. |
| 0:45–1:30 | **Подозрительный перевод** | Откройте карточку операции: объясните вклад крупной суммы, нового получателя и устройства; отметьте, что срабатывание требует проверки аналитиком. |
| 1:30–2:15 | **Серия переводов** | Покажите, как история предыдущих операций влияет на правила частоты. Отметьте, что оценки не используют будущие операции. |
| 2:15–3:15 | **Сеть получателей**, затем **Цепочка переводов** и **Цикл → Граф связей** | Покажите направления переводов, fan-in, последовательное движение средств и замкнутый цикл. Графовые аномалии являются сигналами расследования, а не доказательством мошенничества. |
| 3:15–4:30 | **ML Analytics** | Покажите версии и источники PaySim, IEEE-CIS, BAF Base и IBM AML, размер их отложенного test, Precision/Recall/F1/PR-AUC и матрицу ошибок из реальных артефактов. Затем отдельно покажите установленную Unified Intelligence как экспериментальную multi-task модель с validation-only метриками. Для модели без артефакта покажите честный статус «не установлена». |
| 4:30–5:00 | **Расследования** | Откройте операцию из очереди, изучите связанные переводы и граф, выберите «Запросить подтверждение», добавьте комментарий и покажите записи журнала. Обновите страницу: статус и события сохраняются в БД. |

После основного показа откройте **ML Analytics** и выполните отдельные запросы к PaySim, IEEE-CIS, BAF и IBM AML по точной схеме каждой модели. В интерфейсе отображаются реальные сохранённые метрики и ответы установленных моделей. Текущий симулятор переводов не содержит всех признаков этих датасетов, поэтому его Rule Engine оценку нельзя выдавать за ML-инференс.

Если Unified-артефакт установлен, покажите его отдельно: у него один общий обучаемый backbone и четыре независимые головы, а не роутер специализированных моделей. До `unified.final_test.json` его карточка обозначена **validation only**; после проверенной однократной final-оценки — **one-time final test**. В Model Comparison не называйте Unified или специализированную модель победителем: для такого вывода нужен идентичный заранее зафиксированный holdout по каждой задаче.

## Проверяемые данные и ограничения

- IEEE-CIS финальный артефакт `ieee_final_v2` получен на размеченном конкурсе с фиксированным последним 15% по `TransactionDT`: 88 581 тестовых операций, Precision 0.526988, Recall 0.414856, F1 0.464247, PR-AUC 0.444182, ROC-AUC 0.875369, FP 1 148, FN 1 804. Перед показом убедитесь, что именно этот артефакт настроен через `IZQAR_MODEL_PATH`; при другом файле показывайте цифры самого файла.
- PaySim v2 обучен на полном синтетическом CSV (6 362 620 строк), локально загружается через переносимый XGBoost JSON и preprocessing. На ранее просмотренном test из 955 744 операций: Precision **0.898085**, Recall **0.690025**, F1 **0.780426**, PR-AUC **0.833058**, ROC-AUC **0.998380**, FP **314**, FN **1 243**. В `.env` должен быть путь `IZQAR_PAYSIM_MODEL_PATH` к `paysim_model_v2_portable.metrics.json`. Это воспроизведение уже просмотренного holdout, не независимое подтверждение нового улучшения.
- Для демонстрации любой специализированной модели в ML Analytics выберите её и используйте шаблон признаков. Для Unified сначала выберите соответствующую голову `Unified · <dataset>`; интерфейс получает её точную схему от API. Значения `null` означают явно отсутствующие признаки и служат только технической проверке контракта, а не реалистичной банковской операцией. Результат каждой модели подписан собственным источником и версией. Не переносите показанный ML-скор в Rule Engine как единый риск.
- `risk_score` ML — исследовательский скор от 0 до 100. Без отдельной проверки калибровки его нельзя называть банковской вероятностью мошенничества.
- IEEE-CIS и PaySim отражают разные типы операций; их метрики не являются прямым сравнением качества алгоритмов.
- Текущий единый API-ключ и SQLite предназначены для локального демо, а не для продуктивной банковской эксплуатации. Журнал действий фиксирует время и источник `local_demo_api_key`, но не может подтвердить личность конкретного аналитика.
