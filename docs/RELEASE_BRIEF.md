# IZQAR — краткий бриф по проекту (для внешнего ревью)

Дата: 20 ноября 2026. Репозиторий: https://github.com/Night011/izqar, ветка `main`, коммит `db45ad2`.

## Что это

IZQAR — исследовательский MVP консоли для выявления и расследования финансового мошенничества.
Не заменяет банковское ядро и не выдаёт «единую вероятность мошенничества»: Rule Engine, ML-модели
и графовый анализ остаются раздельными источниками сигналов, аналитик принимает решение.

Стек: FastAPI + Pydantic + SQLAlchemy/SQLite, React + TypeScript + Vite + Cytoscape, XGBoost +
scikit-learn для четырёх специализированных моделей, PyTorch для экспериментальной multi-task сети,
NetworkX для графа.

## Что уже работает (проверено на живом стенде 20.11.2026)

- 6 демо-сценариев (обычная оплата, новый получатель, серия переводов, fan-in, цепочка, цикл);
- Rule Engine объясняет срабатывания на демо-операциях;
- граф связей: 23 узла / 19 рёбер на демо-истории;
- ML Analytics: реальные метрики и пороги из артефактов;
- 5 ML-предиктов: PaySim, IEEE-CIS, BAF Base, IBM AML + Unified (эксперимент);
- расследование: статусы, комментарии, журнал, прикреплённая ML-оценка;
- 162 backend-теста проходят; React production build успешен;
- нет артефакта — нет прогноза (503), фиктивных ответов нет.

## Что измерено в research, но НЕ в проде

- BAF: 6-армовый ансамбль даёт mean PR-AUC 0.1774 против 0.1640 у прод-конфигурации (валидационные
  фолды, corrected protocol TRAIN → CALIBRATION → OUTER VALIDATION).
- IEEE-CIS: конфигурация v3 даёт 0.5074 на том же историческом тесте и 0.5765 в research-CV против
  0.4442 у прод-артефакта; кандидат не промоутнут.
- PaySim: при бюджете 100 FP/10k единый порог под бюджет даёт recall 1.000 при 11.2 FP/10k, тогда как
  текущий max-F1 порог даёт recall 0.769 при 0.56 FP/10k. Per-type пороги не дают ничего сверх этого.

Причина, по которой research не в проде: это изменение прод-контракта и требует отдельного релиза,
переобучения/экспорта и повторной проверки.

## Ограничения (сознательно не скрываются)

- research MVP, не production: один demo API-key, SQLite, нет RBAC и неизменяемого аудита;
- ML-артефакты не в Git (кладутся в `backend/models/` из проверенного экспорта);
- CI не проверялся (GitHub Actions заблокированы billing lock) — зелёный CI не заявляется;
- Docker-сборка не прогонялась в этот релиз;
- потоковых счётчиков (velocity-признаки BAF) нет — только в roadmap.

## Варианты развития (после подачи)

1. Промоут IEEE-кандидата (0.4442 → 0.5074 на том же тесте) через отдельный релизный контур с
   фиксированным артефактом и повторным smoke.
2. Промоут BAF-ансамбля (0.1640 → 0.1774) с сохранением fixed-threshold контракта.
3. Бюджетный operating point PaySim: порог под FP-бюджет вместо max-F1, с rolling-окном оценки.
4. Потоковые счётчики для BAF (7 velocity-признаков) + rolling score window.
5. Калибровка скоров на корректно выделенных данных.
6. Корпоративные роли, аудит, мониторинг drift; Docker/CI.
